# ⚡ Оптимизация скорости обучения

## 🔍 Почему модель учится медленно?

### Математика замедления:

**Было (оригинальная модель):**
- Sequence length: 60
- Prediction horizon: 10
- **Сложность:** 60 × 10 = **600**

**Стало (текущая конфигурация):**
- Sequence length: 600
- Prediction horizon: 100
- **Сложность:** 600 × 100 = **60,000**

**Замедление:** 60,000 / 600 = **в 100 раз медленнее!** 😱

---

## 📊 Варианты конфигураций

| Вариант | Seq Length | Pred Horizon | Сложность | Скорость | Качество | Когда использовать |
|---------|-----------|--------------|-----------|----------|----------|-------------------|
| **Original** | 60 | 10 | 600 | ⚡⚡⚡⚡⚡ | ⭐⭐⭐ | Baseline (то что было) |
| **Fast** | 120 | 30 | 3,600 | ⚡⚡⚡⚡ | ⭐⭐⭐⭐ | **Рекомендуется для экспериментов** |
| **Balanced** | 300 | 60 | 18,000 | ⚡⚡⚡ | ⭐⭐⭐⭐⭐ | Production (баланс) |
| **Quality** | 600 | 100 | 60,000 | ⚡ | ⭐⭐⭐⭐⭐⭐ | Максимальное качество |

## 🚀 Дополнительные оптимизации скорости

### 1. Увеличьте batch size

```python
# В config.py
batch_size: int = 64  # Было 32

# Если есть память, можно еще больше:
batch_size: int = 128  # В 2 раза быстрее
```

**Эффект:** Почти линейное ускорение
- batch=32 → 1x
- batch=64 → 1.8x быстрее
- batch=128 → 3.2x быстрее

### 2. Уменьшите количество эпох для тестов

```python
# Для быстрых экспериментов
num_epochs: int = 30  # Вместо 100
early_stopping_patience: int = 10  # Вместо 20
```

### 3. Используйте подвыборку данных для тестов

```python
# В run_training.py, после загрузки данных:
if QUICK_TEST:
    df = df.sample(n=5000)  # Используем только 5000 строк
```

### 4. Отключите некоторые фичи (временно)

```python
# В config.py
use_attention: bool = False  # Attention замедляет на ~20%
bidirectional: bool = False  # Bidirectional удваивает вычисления
```

    prediction_horizon = 30
    batch_size = 64

    sequence_length = 300

    batch_size = 64
