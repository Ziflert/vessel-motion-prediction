# 📉 MINIMAL_DATASET — необходимый минимум параметров (обоснование)

> Создан: 2026-09-28 (вопрос заказчика: «зачем кормить нейросети 5 тыс. значений,
> которые не нужны или не изменяются»). Артефакты: `data/raw/your_data_minimal.csv`
> (17 колонок), скрипт `scripts/make_minimal_dataset.py`, профиль
> `minimal_prediction` в `config/config.py`. Направления ветра/волнения в нейросеть
> НЕ подаются как абсолютные значения — инженерия признаков считает КУСОВОЙ УГОЛ
> (Wave/Wind.direction − Course, sin/cos).

---

## 1. Что убрано (22 колонки из 39) и почему

| Колонка | Почему убрана |
|---|---|
| Velocity.Yawing(°/мин) | дубликат ROT в производной форме |
| Swell(метры) | сценарный параметр, corr(Roll) ≈ −0.003 |
| Wave.current(метры) | неоднозначный канал, corr(Roll) ≈ −0.04 |
| Swell.direction(градусы) | константа, не используется в признаках |
| Current.direction(градусы) | константа (течение не менялось) |
| Current.speed(узлы) | константа (нулевое течение) |
| Long / Lat(градусы) | координаты (судно в одном районе, не признак поведения) |
| STW(узлы) | дубликат SOG |
| Moment Yawing/Rolling/Pitching (3) | вычисленные ЭФФЕКТЫ — следствие качки, а не причина; кормить ими модель = цикличность |
| Force Vertical/Summary/Longitudinal/Lateral (4) | то же |
| Wind.Moment Yawing/Rolling/Pitching (3) | вычисленные ветровые эффекты |
| Wind.Force Vertical/Longitudinal/Lateral (3) | вычисленные эффекты |

⚠ **Wind.Force Summary ОСТАВЛЕН** — единственный прокси интенсивности ветра в записи
(канала Wind.speed нет; corr(SOG, Wind.Force) = −0.25). При сборе с Transas заменить
на реальную скорость ветра (узлы).

## 2. Необходимый минимум — ОСТАВЛЕНО (17 колонок)

| Группа | Колонки | Роль |
|---|---|---|
| Качка (цели) | Pitch, Roll, Vertical, Velocity.Pitching/Rolling/Vertical | 6 целей full_prediction |
| Навигация | SOG (цель/скорость), ROT (цель/контур «руль→ROT→курс»), Course | основа КУ |
| Управление | **Rudder Order** (заданная перекладка), **Rudder State** (фактическая), RPM (нагрузка) | главная зависимость «руль→ROT» (§5.7.6) |
| Внешние условия | Wave.Highest (тяжесть состояния), Wave.speed (прокси периода/частоты встречи), Wind.Force Summary (прокси ветра) | состояние среды |
| Основы КУ | Wave.direction, Wind.direction (константы — для расчёта курсовых углов) | инженерия КУ |

**Ключевой принцип (указание заказчика):** направления ветра/волнения НЕ подаются в
нейросеть как абсолютные значения — инженерия признаков считает **КУСОВОЙ УГОЛ**
(Wave.direction − Course; Wind.direction − Course) и кодирует sin/cos
(`relative_wave_angle` + `relative_wind_angle` в data/features.py; 2026-09-28).
Константные sin/cos абсолютных направлений после StandardScaler обнуляются
(std=0 → масштаб 1 → 0) и на модель не влияют.

**Итог:** 17 колонок CSV → **24 переменных входа** (было 25 при full_prediction с
лишними каналами). Параметры модели: ~475.3k (прирост < 0.2 % — см.
`scripts/param_count_analysis.py`).

## 3. Как предсказывают поведение в шторм — литература (библиотека research-article)

Проверено 2026-09-28 (веб-поиск + карточки библиотеки `research-article/analysis/`):

| Статья | Входы модели | Что берём |
|---|---|---|
| **Edwards 2023** (LSTM, бимодальные моря, arXiv 2307.08810) | heave/roll/pitch (от SimpleCode) + **волновая элевация у ЦТ на заданной скорости/курсе + наклон волнового поля x/y** (бимодальность); **относительные углы волны 0–330° через 30°**; отдельная сеть на каждый КУ | относительный КУ — ключевая входная величина; качка + волновой вход, БЕЗ координат/моментов/дубликатов |
| **Tian & Song 2023** (App. Sci. 10.3390/app13095298) | волна (элевация 1/3/5 точек) + качка; схема с волной **существенно** повышает точность и горизонт упреждения против чистой автогрегрессии | волнение — главный возбуждающий фактор; вход волны обязателен |
| Таблица 1 (Tian&Song, обзор 20 моделей) | входы: sway / 6-DoF motion / state attributes / roll / pitch / heave — состояние судна + волна | никто не использует: координаты, STW-дубликаты, моменты/силы как входы |
| Li et al. 2017 (NARX) | **29 state attributes** судна → heading, roll, pitch | состояние судна достаточно для контуров управления |

**Консенсус литературы** (совпадает с нашим минимумом): качка (позиции/скорости) +
параметры волны (высота/элевация, период, **относительный угол**) + скорость/курс +
руль/нагрузка. НЕ используются: координаты, дубликаты каналов, вычисленные моменты/силы,
константы-направления как абсолютные значения.

**Важно из Edwards 2023 для нашего сбора:** обучение по сетке **relative wave headings
0–330° через 30°** при фиксированной скорости — тот же принцип, что и схема заказчика
(КУ через манёвры курса); bimodal (ветер + зыбь) — два спектра.

## 4. Использование

- **Обучение на минимуме:** `.venv/Scripts/python.exe run_training.py --data-path
  ./data/raw/your_data_minimal.csv --profile minimal_prediction ...`
  (профиль `minimal_prediction`: вход 24, цели 8, веса как full_prediction; проверено
  смоук-тестом 2026-09-28).
- **Полный формат остаётся** для анализа (`data/raw/your_data.csv`) — моменты/силы
  полезны для диагностики/статьи, но не для обучения.
- При сборе с Transas (план v1.1) целевой формат = минимальный + реальная скорость ветра
  + период волны T_w вместо прокси.
