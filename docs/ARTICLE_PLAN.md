## 1. Одна статья или несколько? — РЕКОМЕНДАЦИЯ: одна основная

Объём работы действительно большой (~50 прогонов Ф0.5–Ф6 + старые E1/E2/E3), но делить
по метрикам (прогоны отдельно, горизонты отдельно, тесты отдельно) НЕ стоит — каждая
часть в отдельности слишком узкая для журнала (получатся технические заметки, а не
исследовательская статья), и новизна размывается. Результаты образуют ЕДИНУЮ историю:

**«Сколько и каких данных нужно для прогноза качки судна»** =
learning curve (объём) → ablation/сweep (состав) → горизонты (на сколько верить)
→ per-regime/per-target (где ломается) → требования к сбору (вывод).

Так одна статья даёт сильный методологический вклад. ЕСТЕСТВЕННОЕ разделение — не по
метрикам, а по сюжету/источнику данных:

| # | Статья | Сюжет | Статус |
|---|---|---|---|
| 1 | **Основная (эта)** — качество прогноза vs объём/состав/горизонт на одной бортовой записи | Одна запись Transas, Seq2Seq LSTM, learning curve + ablation + свип + горизонты + режимы | **Сейчас (N2)** — всё готово |
| 2 | Sim-to-real перенос: «много симулятора + немного реального» | После сбора данных (N1/B1): повторить E2/E3 со схемой «симулятор → реальность» вместо «генератор → реальность»; сравнение со статистическим генератором | После N1 |
| 3 | Неопределённость в контуре: MC-Dropout + доверительный контур + детекторы аномалий в онлайн-системе | После N4 (MC-Dropout) и N9 (A4 мультисид playback) | После N4 |

Параллельно можно вести на двух языках: русский (`article_v2_ru.md`) — основная;
английский (`paper-draft.md`) — для подачи в JMSE / Ocean Engineering / OMAE /
Applied Ocean Research.

### 2.1 Свежие данные: E-цикл на реальных записях Transas (2026-10-02) — ГОЛОВНОЙ сюжет

Вторая партия реальных записей (w-5/6/7, попутное волнение, ~2 ч каждая) после конвейера
обработки (`convert_transas_csv.py` → склейка → EDA → режимная синтетика) даёт датасет
**71 000 строк** — и полный контрольный цикл E1T/E2T/E3T/E3TBAD/E3TFULL/E3TDOSE
(сводка `results/e3_controls/report.txt`, RESEARCH_LOG «Запуск контрольных серий E-цикла»).

**Сравнение 12к ↔ 71к строк (головной аргумент статьи):**

| | your_data (12 499 строк, шторм) | real_w5w6w7 (71 000 строк, попутная) |
|---|---|---|
| Train (max) | 5 949 строк (K=9) | 49 700 строк (FULL) |
| MAE (physical overall) | 6.03 (production K=9) | 0.489±0.040 (E3TFULL) / 0.488 (E1T FULL) |
| R² | 0.65 | 0.674 / **0.703±0.019** |
| Skill vs persistence | +0.46 | **+0.60** |

⚠ **Честность (обязательно в тексте):** прямое сравнение MAE 6.03 vs 0.49 НЕ корректно
как «эффект объёма» — датасеты из РАЗНЫХ погодных сценариев (нарастающий шторм до 10.8 м
против попутной волны, roll max 2.4°): целевая амплитуда отличается на порядок.
Корректные формы сравнения:
1. **Skill vs persistence и R²** — относительные метрики: +0.46→+0.60 и 0.65→0.70
   при ×5.7 объёма — это и есть эффект данных/обработки.
2. **Кривая объёма ВНУТРИ нового датасета** (E1T K=2→16→FULL: 1.110→0.740→0.488,
   skill +0.09→+0.40→+0.60) — чистый эффект объёма без конфаундера сценария.
3. **Сопоставимые точки объёма**: старый 5 949 строк (skill +0.418) ↔ новый E1T K=8
   ~5.6k строк (skill +0.366) — при равном объёме skill сопоставим: объём сам по себе
   не даёт выигрыша, выигрыш даёт ВЫХОД на правую часть кривой (49.7k).

**Контрольные серии (доказательная база аугментации — второй сюжет):**
- E3TBAD (негативный контроль, чужая калибровка): 4.05±3.28 — калибровка критична
  и дестабилизирует обучение (разброс по сидам ×7);
- E3TFULL: паритет с реал-only при полном объёме — аугментация не вредит;
- E3TDOSE (дозовая кривая при K=2): 1.110 (0k) → 0.944 (5k) → 0.933 (10k) →
  0.862 (30k) → 0.877 (70k) — насыщение к ~30k, максимум пользы 10–30k;
- польза аугментации концентрирована в мало-данных режиме (на K=8 — паритет с E1T K=8).

Новые рисунки: fig8 (дозовая кривая E3TDOSE + контроли E3TBAD/E3TFULL), fig9

### 3.3 Данные

### 3.4 Методы
- Архитектура: Seq2Seq MLP → LSTM 128×2 → attention → LSTM-декодер 96, вход 24, цели 8
  (Pitch/Roll/Vertical + скорости, ROT, SOG). Окно истории → 20 шагов.
- Инженерия признаков: относительные КУ (Wave/Wind.direction − Course, sin/cos,
  `relative_wave_angle`/`relative_wind_angle`) — ключевой пункт (лит. поддержка: Edwards 2023,
  Tian & Song 2023).
- Протокол оценки: фиксированный тест, fixed scaler (target-скалер из ПОЛНОГО train),
  subset-seed 123, 3 сида {42,43,44}, mean±std — мультисид (R-D1 ✅).
- Гейт «мёртвых» участков `check_target_signal()` — встроен в пайплайн (урок E-1).
- Метрики: MAE, R², skill score vs persistence. Per-regime границы 1.5/4.7/7 м.

### 3.6 Обсуждение
- Ответ на H1: рост с объёмом есть, но на малых n доминирует разброс подмножества/сида;
  степенной закон пайплайн-зависим. Экстраполяция: MAE 6.0 → ~22.5k строк (~6.3 ч).
- Ответ на H2 (старые E2/E3 — как историческое обоснование): синтетика даёт R² 0.63 ≈
  99 мин реальной записи; аугментация поднимает 12 мин до 0.616; перенос избирателен.
  Статистический генератор не воспроизводит контур «руль→ROT→курс» → симулятор снимет
  ограничение (аргумент для статьи №2).
- Практический вывод: требования к сбору — покрытие условий важнее объёма; ~30k строк
  (8 ч) симулятора на состояние загрузки; повторять перекладки 15° в/л многократно.
- Границы: одно судно, одна запись, n=1 на ячейку манёвров (12 эпизодов); research-only.
